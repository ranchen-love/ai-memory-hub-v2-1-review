# README 多语言维护与验收约定
## 默认语言与首页定位
根目录 `README.md` 为简体中文默认首页；英文与其他七种语言在 `docs/i18n/`，保留九语言导航及可用的相对链接。
**README 面向首次接触项目的用户，优先说明价值、功能、信息覆盖范围与设计方法。** 不应演变为安装手册或命令行参考。所有具体参数、JSON 请求与发布流程集中在 [Agent 初始化指南](agent-onboarding.zh-CN.md)和[英文指南](agent-onboarding.md)。
## 信息架构
中文和英文主 README 采用同样的八章顺序：
1. 主要功能：跨 Agent 上下文、人生档案、长期规则、L0–L3、项目、文件、候选治理、版本确认与私人仓库；
2. 保存的信息领域：12 类人生档案、52 领域、134 字段及其他记忆资料方向；
3. 典型使用场景：用户目标与系统支持；
4. 数据结构与设计原则：19 模块、Workspace、Vault、经审 Git 投影；
5. 开始使用：**仅一段含完整通用仓库 URL 的可复制 Agent 指令**，集中授权与最终交付；
6. 隐私、安全与控制权：保护原始资料、审批与不同同步状态；
7. 当前建设状态与适用范围：已实现、已验证和真实外部权限限制；
8. 文档导航与长期方向：详细技术指南的统一入口。
章节标题采用正式、清晰的书面语。每项设计意图在功能章节解释一次，不重复插入 CLI 细节。英文遵循同一用户旅程；其它七种语言保留现有译文与导航，扩展翻译须如实反映当前 V2.4 能力。
## 自助部署的真实边界
首次使用时，用户把通用项目链接和第五章的一段指令交给**确实有仓库读取、本地执行及必要 GitHub 权限的 Agent**。程序提供 `onboarding plan/apply/report`、19 模块 Workspace/Vault 初始化、来源授权与分类整理、待审脱敏 Git 投影及 Private 仓库创建/发布工具。用户需要分别批准敏感读取、正式记忆激活、投影内容、远端操作与持续调度。
仓库当前保持 Private，未获授权的陌生用户/Agent 无法直接访问。真实 GitHub 账号发布尚未完成独立授权的实际验证；模拟远端测试不可表述为生产环境验收。任何平台未提供的会话/附件数据都必须如实标记缺失，不能编造。
`AGENTS.md` 是执行端入口，具体参数见[Agent 首次部署协议](agent-onboarding.zh-CN.md)。个人 Workspace 默认禁止整体 Git 跟踪，敏感原文、Vault、附件字节与凭据不得默认发布。Vault `2.1`、Workspace `1.0`、离线传输 `2.2` 兼容协议保持不变。
## 自动验证
`scripts/check_readme_i18n.py` 检查九语言导航、站内链接、结构、L0–L3、主 README 的单一复制指令、代码块无空行与首页无冗长 CLI。不要再要求首页包含合成安装脚本或 transfer 命令；它们属于独立操作指南。
Windows/Ubuntu CI 与严格发行白名单、ZIP、Bundle、历史凭据扫描仍为合并条件。用户私人数据、文件字节和实际 Vault 不得纳入通用发行文件。
